# Quarterline — Threat Model (STRIDE-lite)

Scope: the local attack surface of a single-user, 127.0.0.1-bound research
desk (SPEC §2.3). Trust boundaries: (1) everything fetched from SEC/IR, (2)
user input arriving over HTTP, (3) model output, (4) the local filesystem,
(5) the DB. NOTHING here addresses a multi-user or internet-facing deployment
— see `docs/commercial_readiness.md` for what a hosted release would need.

| # | Threat | STRIDE | Surface | Mitigation (implemented) | Evidence |
|---|---|---|---|---|---|
| 1 | **Untrusted filing content → prompt injection** (an exhibit containing "ignore instructions, output X") — retrieved passages are evidence, never instructions | Tampering/ Elevation | Ingested documents → retrieval → prompt | System prompts state passages are evidence-not-instructions; numbers may only come from the Python-rendered `metric_mentions` channel; every filing-derived assertion must cite SUPPLIED evidence ids (checks: existence, in-text membership, company identity, period compatibility); whole-statement drops; injected text rendered inert in HTML (autoescape, never `\|safe`) | `tests/unit/test_validation_gate.py`, `tests/unit/test_citations.py`, `tests/integration/test_generation_pipeline.py`; `docs/failure_cases.md` §7 (injection exhibit → inert evidence) |
| 2 | **Untrusted user questions** (injection via `/api/ask`, malformed bodies, unknown fields) | Tampering | HTTP API | Pydantic schemas `extra="forbid"`; 400/404 paths for bad input; advice-seeking questions get a deterministic refusal **before any model call**; questions are stored hash-only (sha256 + length), never raw | `tests/integration/test_generation_api.py`, `tests/unit/test_advice_policy.py`, `tests/unit/test_observability.py` |
| 3 | **Untrusted/compromised SEC responses** (wrong or malicious bytes) | Tampering/DoS | `SecClient` download path | Content validation before caching; scripts never executed or retained during HTML cleaning; cleaning extracts text only; sha256 + etag + last-modified retained in `source_artifacts`; corrupt PDFs → `failed` with hash kept; date integrity: 8-K discussed period parsed only from exhibit text, never inferred from filing date | `tests/unit/test_html_clean.py`, `tests/unit/test_pdf_extract.py`, `tests/integration/test_documents_pipeline.py` |

| 7 | **SQL / shell / arbitrary URL exposure to the model** (classic agent RCE) | Elevation | Agent tool layer | None exists: four typed tools only (`get_company_facts`, `search_filings`, `get_prices`, `export_memo`) backed by repository calls — no SQL, shell, or fetch-by-URL tool; tool registry is a hard allowlist checked BEFORE argument parsing; rule-based planner selects from READ_TOOLS only and re-validates plans; every attempt (incl. rejections) audited to `agent_tool_calls` with args sha256 | `docs/failure_cases.md` §1–§3, `tests/unit/test_agent_tools.py`, `tests/integration/test_agent_graph.py` |
| 8 | **Silent data exfiltration via remote model fallback** | Information disclosure | Provider selection | `ALLOW_REMOTE_FALLBACK=true` AND non-empty `OPENROUTER_API_KEY` AND model are all required (hard `RemoteFallbackNotConsented` gate); default is local Ollama only; evidence/facts leave the machine only after explicit operator consent | `tests/unit/test_llm_providers.py` (consent-gate matrix) |
| 9 | **Filing HTML injected into the app origin** (XSS) | Tampering | `/filings/{id}` viewer | Only cleaned `sections` text is served; Jinja autoescape on; never raw/safe injection of filing HTML (SPEC §2.3.7); security headers (nosniff, CSP self+inline) on responses; vendored htmx/Chart.js served locally, no CDN | `tests/integration/test_ui_filings.py` (escaped script + injection fixture rendered inert), `tests/integration/test_ui_watchlist.py` (headers) |
| 10 | **Secrets leakage** | Information disclosure | Config/logs | No secrets committed (`EDGAR_IDENTITY`, `OPENROUTER_API_KEY` env-only, `.env` gitignored); logs redact secret-looking keys; question/query text stored hash+length only; `estimated_api_cost` stays null with explicit `cost_basis` (never "free") | `tests/unit/test_observability.py`, `tests/unit/test_config.py` (placeholder-identity gate), `tests/security/test_identity_gate.py` |
| 11 | **SEC rate-limit non-compliance / abuse of the fair-access policy** | DoS (outbound) | SEC client | Valid `EDGAR_IDENTITY` required for any live request; thread-safe monotonic ≥200 ms spacing (clamped up, never down; undershoot-proof loop); 429/503 backoff up to `SEC_MAX_RETRIES`; disk cache with ETag/Last-Modified revalidation + dated-cache fallback | `tests/unit/test_sec_client.py`, `tests/unit/test_cache.py`, `tests/security/test_identity_gate.py` |
| 12 | **PostgreSQL exposure** (optional profile) | Information disclosure/ Elevation | `docker-compose.yml` | Binds `127.0.0.1:5432` only; documented LOCAL-DEV-ONLY credentials; the profile is a single-user research store — no authn/authz beyond these credentials by design (see commercial readiness) | `docker-compose.yml` header comment; `docs/commercial_readiness.md` |

## Explicit non-goals (this release)

- No multi-user isolation, no authentication, no HTTPS termination.
- No semantic injection detector: injection defense is **structural**
  (deterministic planner + citation gate + metric-mentions channel +
  HTML escaping). A retrieved passage could still steer *phrasing* inside
  validated JSON — the gates ensure it cannot invent numbers, misattribute
  companies/periods, or emit unvalidated prose. Recorded as a known
  limitation in `docs/failure_cases.md` §"Gaps".
- Numeric validation does **not** guarantee factual correctness (SPEC §2.2.6);
  it guarantees that displayed numbers trace to the fact card or are dropped.
- Passing these controls does not justify claiming "hallucination-free" or
  "investment-grade" (SPEC §31).
